# Cocos Creator 2D 新手踩坑汇总（结合你跳跃小游戏+UI卷轴实战遇到的全部问题）
按模块分类，附带现象、根因、标准解决方案，方便复盘。

## 一、节点层级 & 渲染遮挡问题
### 1. UI背景面板盖住按钮/文字
**现象**：Bg背景渲染在按钮上方，交互元素看不见
**原理**：同Layer下，层级管理器**从上到下依次渲染，下方节点后绘制、覆盖上层节点**
**错误结构**
```
StartMenu
├ Button
├ Bg
```
**正确结构**
```
StartMenu
├ Bg（背景放最上方，优先绘制）
├ Button
├ Title
```
✅ 要点：**不要依靠Z坐标控制UI前后；2D UI同层仅受节点树顺序控制**

### 2. 场景物体与UI互相重叠、菜单跟着画面滚动
**现象**：相机跟随玩家滚动时，开始菜单一起左右漂移
**根因**：场景、UI全部放在同一个Layer，单相机统一渲染
**解决方案：双相机 + Layer分层体系**
1. 物体分层打标签
   - 玩家、地面方块：`Layer = DEFAULT`
   - StartMenu、按钮、Bg、文字：`Layer = UI_2D`
2. 两台相机分别设置 `Visibility`（可见掩码过滤器）
   - 场景跟随相机：仅勾选 `DEFAULT`（只渲染游戏世界）
   - UI静态相机：仅勾选 `UI_2D`（只渲染界面）
3. 相机顺序：场景相机放上方，UI相机放下方；先渲染场景，再渲染UI，保证界面置顶
> ⚠️关键提醒：**只改物体Layer，不修改相机Visibility = 分层完全无效**

## 二、Sprite 图片面板相关（九宫格）
### 3. 面板拉大后圆角、边框变形
**现象**default_panel素材拉伸后四角被压扁
**根因**：Sprite Type 使用默认 `SIMPLE`（整张均匀缩放）
✅修复：
1. Sprite Type 修改为 `SLICED`（九宫切片）
2. 在资源编辑器打开图片，绘制九宫分割线
3. 修改UITransform Content Size自由调整面板大小
四种Type快速区分：
- SIMPLE：整体缩放
- SLICED：九宫格，保护边角不变形（弹窗/按钮背景专用）
- TILED：图片重复平铺
- FILLED：进度条、遮罩

## 三、相机卷轴（跟随玩家滚动）相关
### 4. 相机跟随方案两个选型与坑
方案A：Camera直接作为Player子节点
- 优点：零代码自动跟随
- 缺点：角色跳跃、移动时画面剧烈抖动，手感差，**仅适合学习测试**

方案B：独立相机 + Lerp平滑追赶（正式项目推荐）
```ts
camera.position.x = math.lerp(camera.position.x, targetPlayerX, 0.08);
```

### 5. 开启相机移动后画面异常、画布锁定
**现象**：相机移动，但场景不会滚动
✅操作：关闭Canvas组件 `Align Canvas With Screen`
作用：解除画布与屏幕强制绑定，画布允许自由偏移，卷轴功能生效。

## 四、坐标、格子对齐问题（跳跃方块核心BUG）
### 6. 玩家跳跃落地，红方块和地面白方块错位
**现象**：跳跃终点偏移，无法精准落到格子中心
常见3大诱因：
1. **常量不统一（最高频）**
道路生成：`block.setPosition(j * BLOCK_SIZE)`
玩家跳跃硬编码数字 `jumpByStep(40)`，和 `BLOCK_SIZE` 数值不一致
✅统一方案：全部导入同一个常量 `BLOCK_SIZE`

2. **坐标系不统一**
方块父节点、玩家父节点不一样，本地坐标基准不同。
✅方案：玩家、场景方块放在同一个父容器

3. 跳跃位移浮点累积误差
✅修复：跳跃结束强制锁定坐标到目标点
```ts
if (this._curJumpTime >= this._jumpTime) {
    this.node.setPosition(this._targetPos);
    this._startJump = false;
}
```

### 7. this.node.getPosition(vec) 新手误区
```ts
private _targetPos = new Vec3();
this.node.getPosition(this._targetPos);
```
- 作用：复用已有Vec3容器，**将节点当前本地坐标写入变量**
- ❌误区：不要理解为返回坐标；不要频繁 `new Vec3()`，产生内存垃圾
- 区分：`getPosition()` = 返回新Vec3；`getPosition(out)` = 高性能复用写法

## 五、道路生成、游戏逻辑相关
### 8. 道路生成逻辑隐患
```ts
if (this._road[i - 1] === BlockType.BT_NONE) {
    this._road.push(BlockType.BT_STONE);
} else {
    this._road.push(Math.floor(Math.random() * 2));
}
```
逻辑目的：**禁止连续两个空方块，防止玩家无路可跳直接失败**
注意：`Math.floor(Math.random()*2)` 输出 0/1，对应 `BT_NONE / BT_STONE`

### 9. 跳跃结束回调 moveIndex 计算错误
落地格子索引公式
```ts
const moveIndex = Math.round(playerX / BLOCK_SIZE);
```
❌错误：使用Math.floor，索引偏移，判定踩空逻辑出错

## 六、状态管理相关
### 10. GameState 状态切换时机问题
```ts
setCurState(GameState.GS_PLAYING)
```
常见坑：
- 直接激活输入，鼠标事件立刻响应，容易误触发
✅解决方案：增加 `setTimeout(0.1s)` 延迟启用玩家输入
- 切换初始化时，忘记重置玩家坐标、清空步数Label

## 七、通用底层认知误区（高频新手思想错误）
1. 不要混淆【本地坐标】与【世界坐标】
`getPosition()` 本地坐标；`getWorldPosition()` 世界坐标；父子嵌套层级越多越容易错位。
2. Layer 只是标签，本身不控制遮挡，**依靠相机Visibility筛选渲染对象**
3. 单相机无法实现「场景滚动、UI固定」，必须双相机分层渲染
4. UI渲染顺序 = 层级树顺序；场景与UI隔离依靠Layer+多相机，不要混用一套坐标系
